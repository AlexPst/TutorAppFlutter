# Репетитор (TutorApp)

Приложение для репетиторов, которые ведут занятия онлайн: ученики и их предметы,
расписание, учёт оплат и долгов, прогресс по темам. Работает без интернета —
все данные хранятся на устройстве.

Платформы: **Android** и **Linux**. Языки интерфейса: **русский** и **английский**.

## Возможности

- **Ученики** — контакты, несколько предметов у одного ученика со своей ставкой,
  шкала оценок (2–5, 1–10, 0–100 или своя), заметки, архив.
- **Расписание** — день, неделя, месяц; быстрые действия «Проведено»,
  «Отменено», «Перенести»; занятия, которые нужно отметить.
- **Оплаты** — платежи, пакеты занятий, автоматический расчёт долга,
  должники с готовым текстом напоминания, отчёт о доходах за период.
- **Прогресс** — оценки за занятия и отдельные записи, освоение тем,
  динамика и график.
- **Главная** — ближайшие занятия, сводка (ученики, доход, долг), топ должников,
  быстрые действия.
- **Настройки** — светлая, тёмная или системная тема; язык.

## Требования

- Flutter **3.44+** (проверено на 3.47.7), Dart **3.13+**.
- Android: Android SDK, устройство или эмулятор.
- Linux: зависимости сборки Flutter для Linux (`clang`, `cmake`, `ninja-build`,
  `pkg-config`, `libgtk-3-dev`). SQLite отдельно ставить не нужно — пакет
  `sqlite3` поставляет её сам.

Проверить окружение: `flutter doctor`.

## Установка и запуск

```bash
git clone <url> tutor_app && cd tutor_app
flutter pub get
dart run build_runner build      # код Drift, Freezed, Riverpod
flutter gen-l10n                 # переводы (также выполняется при сборке)

flutter run -d linux             # Linux
flutter run -d <android-device>  # Android: список — flutter devices
```

Сборка релиза:

```bash
flutter build apk --release      # Android
flutter build linux --release    # Linux: build/linux/x64/release/bundle/
```

Где лежат данные: на Linux — `~/.local/share/com.dartway.tutor_app/tutor_app.sqlite`,
на Android — в каталоге данных приложения.

## Разработка

| Задача | Команда |
|---|---|
| Генерация кода после правки моделей, таблиц, провайдеров | `dart run build_runner build` (или `watch`) |
| Переводы после правки ARB | `flutter gen-l10n` |
| Анализатор (flutter_lints + riverpod_lint) | `flutter analyze` |
| Тесты | `flutter test` |
| Снимок схемы БД для миграции | `dart run drift_dev make-migrations` |

### Тесты

- **Domain** — правила оплаты (пакеты FIFO, возвраты), use cases занятий,
  платежей и прогресса, расчёт баланса и сводок, динамика оценок.
- **Репозитории** — на настоящей SQLite в памяти: расчёт долга по всем статусам,
  отчёт о доходах на границах периода, статистика, хронология прогресса.
- **Виджеты** — сценарии ключевых экранов (список учеников, форма занятия,
  финансы, прогресс, главная), английский интерфейс, настройки, ошибки.
- **Локализация** — одинаковые ключи в ru/en, перевод каждой причины ошибки,
  а также проверка, что в коде нет русских строк в обход ARB.

Виджетные тесты с Drift пишутся через `testAppWidgets` и `pumpApp`
из `test/helpers/pump_app.dart`: они фиксируют время, язык и закрывают
стримы БД после теста.

### Локализация

Строки интерфейса — в `lib/l10n/app_ru.arb` (шаблон) и `lib/l10n/app_en.arb`.
В коде — `context.l10n.ключ`. Склонения — ICU plural
(`{count, plural, one{…} few{…} many{…} other{…}}`). Domain не содержит текстов:
ошибки передают код причины (`FailureReason`, `FieldError`), а перевод подбирает
`lib/l10n/l10n.dart`. Даты, время и суммы форматируются по текущей локали
(`Formatters`); валюта всегда рубли.

## Архитектура

Feature-first + упрощённая Clean Architecture:

- **presentation → domain ← data**. Domain — чистый Dart без Flutter и Drift.
- Состояние и DI — **Riverpod 3** (`@riverpod`, генерация).
- Данные — **Drift (SQLite)**; запросы реактивные (`watch`), поэтому экраны
  обновляются сами после любой операции.
- Баланс не хранится, а вычисляется SQL-агрегатами из занятий, пакетов
  и платежей — он не может разойтись с данными.
- Use cases выполняются в транзакции (`TransactionRunner`): оплата занятия,
  оценка и прогресс меняются атомарно.

Бизнес-правила оплаты и прогресса описаны в документации к use cases
(`lib/features/*/domain/usecases/`) и в `docs/requirements.md`.
